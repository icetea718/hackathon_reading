# AI 阅读器 App — 设计文档

- 日期：2026-11-03
- 状态：待用户评审
- 项目目录：`F:\hackathon_reading`

## 1. 意图与背景

做一个**本地优先**的阅读器 App，主要运行在 **Windows 和 Android**。它首先是一个可靠的阅读器，其次是一个可持续扩展的 **AI 陪读 / agent 平台**：AI 翻译、划重点解读、陪读对话是后续核心方向，但具体形态尚未确定。

因此第一版（MVP）的目标不是把 AI 做全，而是：**把阅读体验和数据结构做扎实，并留出不返工的 agent 接入点。**

## 2. 目标（MVP）

1. 导入 EPUB / TXT / PDF 三种格式。
2. 识别书本的章节/部分结构，提供可跳转的目录；文件本身没有章节信息时自动识别。
3. 基础阅读：书签、高亮、文字笔记、记住上次阅读位置。
4. 简洁可用的阅读界面雏形（中文优先）。
5. 预留 agent 层：接口、上下文构建、划词入口、设置项。
6. Windows 和 Android 都能实际运行；浏览器（Flutter Web）仅用于体验测试。

## 3. 非目标（MVP 明确不做）

- iOS / macOS 适配。
- 账号系统、云同步、多设备进度同步。
- TTS、听书、书源/书城、下载。
- PDF 重排（reflow）。
- 真实调用大模型（只留接口与占位 UI）。
- 复杂排版、插图排版、自定义字体商店。
- 阅读统计、成就、社区。
- 用户可见的备份/恢复 UI：MVP 只保证磁盘上的数据布局稳定、可手动备份；导出/导入功能后续再做。

## 4. 反目标（即使功能跑通也算失败）

- **章节识别依赖大模型**：基础解析必须离线可用，LLM 只能是可选增强。
- **标注数据与渲染方式强耦合**：换字体、换窗口大小、换设备后高亮错位。
- **AI 能力与某一家模型厂商写死**：以后换供应商不应重写阅读器。
- **一次性大爆炸交付**：必须能按里程碑逐步运行、逐步提交。
- **导入后书丢了、笔记丢了**：本地数据必须可预期、可备份。

## 5. 约束

- 开发机：Windows 11。
- **Flutter SDK 当前未安装**，Android SDK/模拟器状态未验证；M0 必须先完成环境搭建。
- 中文阅读场景优先：TXT 必须覆盖 UTF-8、GB18030/GBK、UTF-16 等常见编码；章节识别要支持"第X章/第X节/序章/番外"等中文标题。
- 离线可读：除 AI 功能外，全部核心功能不依赖网络。
- 性能目标（MVP）：单本 TXT/EPUB 不超过 50 MB 或 2000 章，PDF 不超过 1000 页，书架不超过 500 本。可重排格式按章节懒加载，PDF 按页虚拟化，不整本一次性渲染。
- UI 先做简洁雏形，视觉细节后续讨论。
- 版本管理：完成一个功能提交一次；每个里程碑结束自行验证，再请用户验收。

## 6. 平台与技术决策

| 项目 | 决策 | 说明 |
|---|---|---|
| 框架 | **Flutter / Dart** | 一套代码覆盖 Windows + Android；Web 仅做体验测试 |
| 本地存储 | **SQLite（drift）** | 书籍元数据、章节、进度、标注、设置 |
| 文件存储 | 应用私有目录（`path_provider`） | 导入时复制原文件，避免源文件被移动后失效 |
| 文件选择 | `file_picker` | Windows/Android 均支持 |
| EPUB 解析 | 优先成熟包（如 `epubx`），实现前验证维护状态；不合格则自研轻量解析器 | 需读取 OPF spine、NCX、EPUB3 nav |
| PDF 渲染 | `pdfrx` 或 `pdfx`，M5 前做选型验证 | 需支持 Windows/Android、书签/大纲读取、缩放 |
| 状态管理 | 推荐 Riverpod；由实施者最终确认 | 避免为简单原型引入过重框架 |
| 密钥存储 | 后续用 `flutter_secure_storage` | MVP 只放设置页占位，不存真实密钥 |

**说明：** 上述包在实现前需要实际验证（维护状态、平台支持、API 能力），选型结果写入对应里程碑的提交说明。这是留给实施者的判断空间。

## 7. 阅读器形态决策

- 可重排格式（TXT / EPUB）第一版采用**滚动阅读**，不做分页。分页留到后续迭代。
- EPUB 正文第一版**自行提取文本并渲染**，不嵌入 WebView。这样可以稳定做文本选择、高亮和位置锚定；代价是牺牲部分 EPUB 样式与复杂排版。图片/复杂 CSS 第一版不保证。
- PDF 保持固定版式：缩放、平移、页码跳转；不做文字重排。
- 中文 UI；基础字号、行距、背景主题（浅色/深色/护眼）可调。

## 8. 数据模型（初版）

```
Book
  id, title, author, format(epub|txt|pdf), sourcePath, coverPath,
  addedAt, lastOpenedAt, metadataJson

Chapter
  id, bookId, index, title, startAnchor, endAnchor, contentText

ReadingProgress
  bookId, anchorJson, percent, updatedAt

Annotation
  id, bookId, chapterId, type(bookmark|highlight|note),
  anchorStart, anchorEnd, selectedText, color, noteText,
  anchorVersion, createdAt, updatedAt
```

说明：`Chapter.contentText` 保存导入时提取的章节文本（TXT/EPUB），避免每次打开和组装 AI 上下文时重复解析；PDF 不需要该字段。`anchorVersion` 用于未来解析器升级后的锚点迁移。

### 位置锚点（关键设计）

| 格式 | 锚点 | 原因 |
|---|---|---|
| TXT | 解码后全文的字符偏移 | 稳定、与字体/窗口无关 |
| EPUB | 章节 ID + 章节内标准化文本的字符偏移 | 自研文本渲染下最可靠 |
| PDF | 页码 + 归一化矩形坐标（0–1）+ 文本片段 | 适配缩放/设备差异 |

锚点必须能**反向定位到 UI 区域**，用于恢复进度和显示高亮。高亮渲染允许容差，找不到精确位置时降级到所在章节开头并提示。

## 9. 章节识别策略

采用**策略链**，按顺序尝试，命中即停：

1. 文件自带目录：EPUB 的 nav/NCX/OPF spine；PDF 的内嵌书签/大纲。
2. 规则识别：
   - TXT：正则匹配 `第[一二三四五六七八九十百千万0-9]+[章节卷回部篇]`、`序章`、`番外`、`Chapter N` 等；结合空行、行长、标点特征降噪。
   - PDF：若解析库能提供字号/字体信息，用"短行 + 较大字号 + 加粗"识别标题。
3. 兜底：整本书作为单一章节，目录至少能跳转到开头。
4. （未来）LLM 策略：作为可选插件，仅在用户开启且规则失效时调用。

策略必须可插拔，每种策略有独立单元测试。

## 10. 模块划分

```
lib/
  app/            # 入口、路由、主题、全局设置
  features/
    library/      # 书架、导入
    reader/       # 阅读视图、目录、主题、进度
    annotations/  # 高亮、书签、笔记
    assistant/    # AI 入口：划词菜单、助手面板（MVP 为占位）
  domain/         # Book/Chapter/Annotation 模型、服务接口
  data/           # 数据库、导入器、格式解析器
  assistant/      # AssistantService、上下文构建、未来的模型适配器
```

原则：**UI 不直接依赖数据库或模型厂商；所有 AI 调用只经过 `AssistantService`。**

## 11. Agent 预留设计

`AssistantService` 第一版定义以下能力（实现体返回 `NotConfigured`，UI 可展示"未配置"状态）：

- `translate(text, targetLang)` — 翻译选中文本
- `explain(text, bookContext)` — 解读划重点内容
- `summarizeChapter(chapter)` — 章节总结
- `chat(bookContext, history, userMessage)` — 陪读对话

以上返回文本的方法从第一版起就用**流式返回**（`Stream`）定义，即使 MVP 实现只返回 `NotConfigured`。这样以后接真实模型时不需要重写接口和 UI。

配套：
- `ReadingContextBuilder`：组装书名、作者、当前章节标题、当前章节文本、选中文本；做长度截断，避免超出上下文。
- Provider 抽象：未来可接 OpenAI 兼容接口、Anthropic 等；API Key 走安全存储。
- MVP 的划词菜单保留"翻译 / 解读"入口，点击后提示未配置，不阻断阅读。

## 12. 导入与阅读流程

**导入：** 选择文件 → 校验格式 → 复制到 `books/<uuid>/` → 解析 → 写入 Book/Chapter → 生成封面（EPUB 封面；PDF 首页；TXT 占位）→ 刷新书架。

**阅读：** 打开书 → 读取上次进度锚点 → 渲染并定位 → 滚动/翻页时防抖保存进度 → 目录抽屉跳转 → 选中文本弹出操作菜单 → 高亮/笔记写入数据库 → 标注面板内可跳回原文。

## 13. 失败处理

- 文件损坏/格式不支持：明确提示，不崩溃、不产生半本书。
- 无章节信息：单章节兜底，仍可阅读。
- TXT 编码识别失败：按 UTF-8 → GB18030 → Latin-1 顺序降级，并允许用户手动指定编码（可后置）。
- PDF 无大纲：目录只提供页码范围，允许按页跳转。
- 扫描版 PDF（无文本层）：仍可阅读；标注能力见第 18 节待确认项。
- 高亮锚点失效：降级定位到章节开头并提示，不删除用户数据。

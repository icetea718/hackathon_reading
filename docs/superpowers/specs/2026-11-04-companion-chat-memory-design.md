# 陪读聊天记忆设计

日期：2026-11-04
状态：已确认。用户选定的三项取舍：前序章节 + 当前章、一章多个线程、旧章节只读回看 + 跳章。

## 目标

把陪读面板从「会话内内存历史」改为本地持久化：

- 聊天按章节保存，关闭面板或重启应用后仍能恢复。
- 同一本书里，已经读过的章节的对话会成为后续提问的记忆，且不剧透后面章节。
- 可以新建、重命名、删除对话；旧章节的对话可以只读回看，一键跳到该章继续。

## 非目标

- 不做跨书记忆、云端同步、全文搜索、编辑已发消息、重新生成、点赞。
- 不把整本书的聊天无上限塞进模型上下文。
- 不用额外的模型调用生成「记忆摘要」。
- 漫画、PDF 没有陪读入口，不涉及。

## 已确认的取舍

1. **记忆范围**：只读取 `chapterIndex` 小于当前章的对话纪要，加上当前线程最近 8 条消息；当前章和后面的章节不进记忆。
2. **对话组织**：每一章可以有多个对话线程，像主流 AI 聊天一样新建、重命名、删除；历史按章节分组。
3. **旧章节对话**：在历史里直接只读打开；想继续聊时点「前往该章」，阅读器跳到该章，面板切到该章并优先打开刚才那条线程（停靠侧栏时；底部面板重新打开时展示该章最近使用的线程）。

## 数据模型（schema v10）

新增两张表，所有字段本地保存：

`companion_threads`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | TEXT PK | UUID |
| `book_id` | TEXT | 所属书 |
| `chapter_index` | INTEGER | 0-based 章节序号；跨章分组、记忆范围都靠它 |
| `chapter_title` | TEXT | 创建线程时的章节标题快照，历史列表直接用 |
| `title` | TEXT | 自动标题或用户重命名 |
| `created_at` / `updated_at` | DATETIME | `updated_at` 用于「最近使用」排序 |

索引：`(book_id, chapter_index)`。

`companion_messages`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | TEXT PK | UUID |
| `thread_id` | TEXT | 所属线程 |
| `role` | TEXT | `user` / `assistant` |
| `content` | TEXT | 完整消息文本 |
| `seq` | INTEGER | 线程内递增序号，保证同一毫秒内顺序稳定 |
| `created_at` | DATETIME | 创建时间 |

索引：`(thread_id, seq)`，唯一。

迁移要求：`from < 10` 时创建两张表和索引；迁移必须可重入（沿用 v6 的 `createTable` + `m.create` 写法）。不修改既有表。

## 记忆装配

一次提问送给模型的上下文由四段组成：

1. 现有的全书蒸馏摘要 + 当前章阅读位置附近摘录（不变）。
2. 当前线程最近 8 条消息（滑动窗口）。更早的消息仍保存在本地，只是不再进入上下文。
3. **前序章节对话纪要**：读取 `chapterIndex < 当前章` 的线程，按 `updated_at` 从新到旧取最多 3 条线程；每条线程取最后 2 条消息，每条消息截到 100 字；拼接成 `【章节名】读者：… 助手：…`；总长 ≤400 字。纯本地规则，不调用模型。当前章和后面的章节不读取。
4. 本次用户消息。

实现位置：面板在发送时通过仓储生成 3，写入 `ReadingContext.companionMemory`；`OpenAiAssistantService` 的系统提示里加入「此前章节的对话纪要」段。assistant 层仍然不直接访问数据库。

## 持久化语义

- 用户消息在发起请求前写入数据库；请求失败时这条消息保留。
- 助手消息只在流式响应完整结束后整条写入；中途失败、切章或被取消时不保存半截回复。
- 当前章被切换时：取消正在进行的请求（旧回复不落库），面板加载新章最近使用的线程；不会把旧章的回复写进新章。
- 删除书籍时级联删除该书的线程与消息。
- 「总结本章」按一次对话处理：先保存一条内容为「总结本章」的用户消息，再把完整摘要保存为助手消息。新线程以「总结本章」为标题。

## 交互

- 面板头部保留「陪读 · 章节名」「停止朗读」「总结本章」「关闭」。
- 头部下方增加两个标签：**聊天** / **历史**。
- 聊天页顶部显示一行记忆提示：第一章显示「暂无前序章节对话」，其余显示「引用之前章节的对话纪要（≤400 字），不读取后面的章节」。
- 首次发送时自动创建线程，标题取第一条消息前 16 个字（超出加 `…`）。通过「新对话」显式创建的线程标题为「新对话」，第一条消息发出时自动改名。
- 历史页按章节分组，当前章置顶并带「当前章」标记；其他章节标「只读」。每行显示标题、时间、消息数；右侧菜单可重命名、删除。重命名为行内输入，带保存/取消。
- 其他章节的线程打开后是只读视图：提示「保存在第 X 章，当前为只读」，展示全部消息，底部「前往该章」。跳章后（停靠侧栏）优先打开刚点击的线程，恢复可输入。
- 删除线程立即生效（不做二次确认，和预览一致）；删除的是正在生成的线程时，先取消请求再删除。
- 未配置 AI 服务时，聊天页仍显示原来的「去设置」提示；但「历史」标签可用，可以继续翻看已保存的对话。

## 失败路径与边界

- 未配置模型：不能发送，已有历史仍可读。
- 请求出错：显示中文错误，用户消息保留，半截助手回复不保存。
- 空白标题：重命名忽略，不清空原标题。
- 长标题：自动标题截断；重命名不限制长度但 UI 单行省略。
- 多个线程同名：允许，用顺序区分。
- 线程内消息很多：UI 展示全部，模型只看最近 8 条。
- 线程消息数为 0：历史里显示「共 0 条」，可删除。
- 删除当前唯一线程后：聊天页回到空状态；还有别的线程时打开该章最近更新的那条。

## 构建者已做的决定

以下细节在预览里没有定死，按工程取舍落定：

- 前序章节纪要用确定性截断，不用模型总结（成本可控、可测试、不会出现新的幻觉）。
- 删除线程不弹确认（与预览一致）。
- 重命名为行内编辑，显式保存/取消，避免失焦误提交。
- 「总结本章」也保存进线程，而不是一次性输出。
- 未配置模型时历史仍可用。
- 跳章后优先打开来源线程；底部面板因为会关闭，重开时展示该章最近使用的线程。

## 验收要点

1. 问一个问题，关闭面板再打开，消息还在；重启应用后仍在。
2. 历史按章节分组；当前章可以新建对话、重命名、删除；旧章节只读打开并可跳章。
3. 在第 3 章提问时，回答能引用第 1、2 章的对话；不会引用第 4 章及以后。
4. 切换章节时面板不会串消息；旧请求不会写到新章。
5. 删除书籍后，其聊天记录与消息一并消失。
6. 不配置模型时历史仍能打开。
